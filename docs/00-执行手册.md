# 00 执行手册：从零到提交

> 对象：通过电控组一轮考核、要做 CVIR 机甲大师 2026 电控二轮考核的同学
> 载体：四自由度舵机机械臂（底座 / 肩 / 肘 / 夹爪），STM32F401CCU6
> 原则：**每一步都有"做完的标志"**，不满足标志不要进入下一步。

## 0 全流程地图

```
第1步 采购 + 装工具链          ~1 天（等快递除外）
  └─ 标志：cmake --version / arm-none-eabi-gcc --version / git --version 都能打印
第2步 CubeMX 建工程 + 编译下载   ~0.5 天
  └─ 标志：空工程能烧进去，LED 能闪
第3步 T0 板级自检               ~0.5 天
  └─ 标志：串口打印工程名/时钟/复位原因，LED 1Hz，按键翻转
第4步 T1 单轴 PWM               ~0.5 天
  └─ 标志：示波器/逻辑分析仪量到 500~2500µs，四路都是 50Hz
第5步 T2/T3 插补 + 限位 + 回零   ~1 天   ← 最难的一步
  └─ 标志：四轴同起同停，越界目标被钳位且 bit2 置位，断电重启零位复现
第6步 T4 I2C + MPU6050          ~0.5 天
  └─ 标志：上报俯仰角误差 ≤3°，拔 SDA 1s 内停并报故障，插回自动恢复
第7步 T5a USB CDC + 协议联调     ~1 天
  └─ 标志：上位机连续 10 分钟无丢帧，拔插 1s 内重连
第8步 选做（T5b/T6/A1/A2）       ~1~3 天（按余力）
第9步 文档、视频、AI.MD、提交     ~1 天
```

**总预算建议 7~9 天**，其中第 5 步和第 7 步最容易被低估，各留 1 天缓冲。

## 第 2 步：CubeMX 建工程

**详细每一项配置见 `docs/01-CubeMX配置清单.md`**，这里只说流程和验证点。

   - 工程名 `ec-round2`，路径选仓库根目录

## 第 3 步：T0 板级自检与供电确认

### 3.1 接线（先只接最小系统）

| 用途 | 引脚 | 说明 |
|---|---|---|
| 调试串口 TX | PA9 | 接 USB-TTL 的 RX |
| 调试串口 RX | PA10 | 接 USB-TTL 的 TX |
| GND | GND | USB-TTL 必须共地 |
| LED | PC13 | 板载，不用接 |
| 按键 | PB12 ↔ GND | 内部上拉，按下为低 |

**舵机电源这一阶段先不要接**，先确认主板自己活着。

### 3.2 把三处接缝填进 CubeMX 生成代码

**① `Core/Src/main.c`**

```c
/* USER CODE BEGIN Includes */
#include "app_main.h"
/* USER CODE END Includes */

/* USER CODE BEGIN 2 */
app_init();
/* USER CODE END 2 */

while (1)
{
    /* USER CODE BEGIN 3 */
    app_loop();
    /* USER CODE END 3 */
}
```

**② 1ms 节拍回调**：写在 `main.c` 的 `USER CODE BEGIN 4`（若 CubeMX 已生成同名回调，把函数体填进去，别重复定义）

```c
/* USER CODE BEGIN 4 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2) {
        app_tick_1ms();
    }
}
/* USER CODE END 4 */
```

**③ USB 回调（这一步做了也没坏处）**：`USB_DEVICE/App/usbd_cdc_if.c`

```c
/* USER CODE BEGIN INCLUDE */
#include "bsp_usb_cdc.h"
/* USER CODE END INCLUDE */

static int8_t CDC_Init_FS(void)
{
  /* ... CubeMX 生成的内容 ... */
  /* USER CODE BEGIN 3 */
  bsp_usb_cdc_on_configured();
  /* USER CODE END 3 */
  return (USBD_OK);
}

static int8_t CDC_DeInit_FS(void)
{
  /* USER CODE BEGIN 4 */
  bsp_usb_cdc_on_reset();
  /* USER CODE END 4 */
  return (USBD_OK);
}

static int8_t CDC_Receive_FS(uint8_t* Buf, uint32_t *Len)
{
  /* USER CODE BEGIN 6 */
  bsp_usb_cdc_on_rx(Buf, *Len);
  USBD_CDC_SetRxBuffer(&hUsbDeviceFS, &Buf[0]);
  USBD_CDC_ReceivePacket(&hUsbDeviceFS);
  return (USBD_OK);
  /* USER CODE END 6 */
}

static int8_t CDC_TransmitCplt_FS(uint8_t *Buf, uint32_t *Len, uint8_t epnum)
{
  /* USER CODE BEGIN 13 */
  bsp_usb_cdc_on_tx_complete();
  /* USER CODE END 13 */
  return (USBD_OK);
}
```

## 第 4 步：T1 单轴 PWM 驱动

### 4.1 先只接一个舵机（底座，PB4）

```
舵机棕线 -> 电源 GND（不是板子 GND！）
舵机红线 -> 5V 2A 电源 +5V
舵机橙线 -> PB4
电源 GND -> 板子 GND   ← 必须共地，否则 PWM 没有参考电平
```

### 4.2 标定（这是 T1 的核心，不是写代码）

1. 打开 `application/app_config.c`，把 `k_servo_cfg[ARM_AXIS_BASE].pulse_min_us`
   临时改成 500、`pulse_max_us` 改成 2500；
2. 用下面这段**临时测试代码**（`app_init()` 末尾）输出三个脉宽，量实际角度：

```c
/* 临时标定代码，标完删掉 */
bsp_pwm_set_pulse(0, 500);  HAL_Delay(1000);
bsp_pwm_set_pulse(0, 1500); HAL_Delay(1000);
bsp_pwm_set_pulse(0, 2500); HAL_Delay(1000);
```

3. 记下 500µs 和 2500µs 对应的实际角度（用量角器或手机水平仪）；
4. 算 `us_per_deg = (2500 - 500) / (角度差)`，填回配置；
5. 若正方向反了，`dir` 改 `-1`；
6. 行程两端各留 5°，填 `angle_min_d10` / `angle_max_d10`；
7. **`pulse_min_us` / `pulse_max_us` 填实测稳定范围**（不要照抄 500/2500，
   很多 SG90 在 2400 以上会抖或堵转）。

### 4.3 用示波器/逻辑分析仪验证（评审就是看这个）

| 判据 | 期望 |
|---|---|
| 周期 | 20.00ms（50Hz），四路一致 |
| 脉宽范围 | 500~2500µs 可调，步进 ≤2µs |
| 线性 | 给 0°/45°/90° 应得到 1500/1950/2400µs（按你的标定） |
| 重复性 | 同一角度命令 10 次，脉宽偏差 ≤2µs |

没有示波器？用逻辑分析仪（十几块的 24MHz 款够用），或者用 USB-TTL 抓——
但**评审现场大概率会要波形**，建议借一个或买一个最便宜的。

### 4.4 四路都标一遍

底座 / 肩 / 肘 / 夹爪分别填 `k_servo_cfg[]` 四行。**四路的 us_per_deg 不要偷懒用同一个值**，
每个舵机的电位器一致性没那么好，这直接影响 T1 的 ±2µs 判据。

## 第 5 步：T2 多轴联动 + T3 限位保护（最难）

### 5.1 先理解代码在干什么

- `components/motion_profile.c`：只算一条**归一化进度曲线** s(t) ∈ [0,1]；
- `application/app_motion.c`：`q_i(t) = q0_i + (q1_i - q0_i) · s(t)`。

所以"同起同停"是数学上成立的，不需要每个轴各写一套。参数在 `app_config.h`：

```c
#define APP_MAX_SPEED_DPS   240.0f   // 太大 -> 丢步/啸叫；太小 -> 动作肉
#define APP_MAX_ACCEL_DPS2  720.0f   // 太大 -> 启停冲击，机械臂会晃
```

### 5.2 联调顺序（不要一上来就四轴）

1. **单轴**：给底座一个 90° 阶跃（profile=1，duration=1500），看是否匀速走、有无过冲；
2. **双轴**：底座 + 肩，同时出发是否同时停；
3. **四轴**：加上肘和夹爪，观察小臂末端轨迹是否平滑（这决定 Q 指标的"平顺度"）。

用上位机（或自己写个串口发包脚本）发 0x20 帧。本仓库提供了发包示例：

```
A5 20 0B 84 03 78 05 B0 04 2C 01 F4 01 02 AB
```

含义：四轴 90.0°/140.0°/120.0°/30.0°，500ms 到位，S 曲线。

### 5.3 T3 限位与回零

判据与代码位置：

| 判据 | 代码位置 | 自测 |
|---|---|---|
| 上电自动回零 | `app_init()` 末尾 `app_state_request(APP_MODE_HOMING)` | 上电后各轴走到 `home_d10` |
| 软限位参数可配 | `k_servo_cfg[]` | 改 min/max 后行为跟着变 |
| 越界目标被钳位 | `app_servo_clamp_target()` | 发 200° 应停在 85° |
| 越界时状态位置位 | `app_protocol.c` 的 `ARM_ST_FAULT`（bit2） | 上位机看到 bit2=1 |
| 不输出超程脉宽 | `servo_map_angle_to_us()` 双重钳位 | 示波器永远在 500~2500 内 |
| 断电重启零位复现 ≤1° | 机械零位靠装配保证 | 断电手动拨到任意位置，上电回零后量 |

> **注意**：本工程把"限位钳位"也表示在 bit2（故障位）上，因为协议没有单独的限位位。
> 评审问起就这样解释：**急停/I2C 故障的 bit2 需要显式复位，钳位的 bit2 在收到下一个
> 合法目标时自动清除**。这句话写进设计说明。

### 5.4 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 运动中途"卡一下" | 主循环被 I2C/打印阻塞 | 确认 I2C 超时 ≤10ms，打印不要放在 200Hz 路径里 |
| 末端轨迹是折线 | 只做了关节空间插补（正常） | 本考核不要求笛卡尔直线，说明清楚即可 |
| 动作明显慢于设定 | 单位换算错（0.1° vs °） | 已修，见 `app_motion.c` 注释 |
| 到位时"点头" | 加速度太大 | `APP_MAX_ACCEL_DPS2` 降到 400~500 |
| 舵机啸叫 | 目标超出机械行程 | 缩小 `angle_min/max` |

## 第 6 步：T4 I2C 姿态检测

### 6.1 接线

```
MPU6050 VCC -> 3.3V（不要接 5V，GY-521 有的模块 5V 也能用但没必要）
GND -> GND
SCL -> PB8
SDA -> PB9
AD0 -> GND（地址 0x68）
```

模块装在小臂或末端，**X 轴指向末端，Z 轴垂直于小臂表面**（与 `components/mpu6050.c`
的注释一致）。装反了不要改代码，改 `MPU6050_PITCH_SIGN` 为 `-1.0f`。

### 6.2 校准

`app_init()` 里已做：上电静止采 200 个样本（约 1s），算陀螺零偏 + 俯仰零位。
串口会打印 `calib=OK`。如果打印 `calib=wiggle`，说明校准期间机械臂在动，重新上电。

### 6.3 判据自测

| 判据 | 怎么测 | 处理 |
|---|---|---|
| 400kHz 读加速度+角速度 | CubeMX I2C 配 400kHz；`WHO_AM_I=0x68` | 不是 400k 会打印 i2c_err |
| 静止零偏校准 | 上电后不动，pitch 应稳定在 0±0.5° | 抖动大 -> 减小 IIR_ALPHA |
| 实测倾角误差 ≤3° | 用量角器把臂抬 30°，对比上位机显示 | 超差先查装配方向 |
| 拔 SDA 1s 内停止并报故障 | 拔线，看 bit4+bit2 是否在 1s 内置位 | 见 `app_protocol_report_sensor()` |
| 插回可恢复 | 插回，200ms 后 bit4 自动清除 | 不需要复位 |

> 注意：I2C 故障**不进入**故障态锁死，否则"重新接入可恢复"就不成立。
> 这也是设计说明里要写的取舍。

## 第 7 步：T5a USB CDC + 协议联调

### 7.1 检查枚举

插上 USB，设备管理器应出现 `STM32 Virtual COM Port`（VID 0483 / PID 5740）。
如果出现"未知设备"：

1. 看时钟：USB 必须正好 48MHz（PLLQ=7），偏差超过 ±0.25% 就枚举不了；
2. 看 HSE：板子晶振是 25MHz 就 `PLLM=25`，8MHz 就 `PLLM=8`，填错必然枚举失败；
3. 看 PA11/PA12 有没有被别的外设占用。

### 7.2 用上位机或自己发包

协议要点（详见 `protocol/arm_protocol.h` 与任务书附件一）：

| 类型 | 名称 | 方向 |
|---|---|---|
| 0x10 | 状态上报（19 字节载荷） | 设备 → 上位机，30Hz |
| 0x20 | 目标角度（11 字节） | 上位机 → 设备 |
| 0x21 | 模式切换（1 字节） | 上位机 → 设备 |
| 0x22 | 急停（1 字节） | 上位机 → 设备 |
| 0x23 | 心跳（1 字节，原样回发） | 双向，1Hz |
| 0x24 | 版本查询/应答（2 字节） | 双向 |

### 7.3 判据自测

| 判据 | 怎么测 |
|---|---|
| 连续 10 分钟无丢帧/乱码/断开 | 上位机挂机 10 分钟，看帧计数与 CRC 错误计数 |
| 拔插 USB 后 1s 内自动重连 | 拔掉再插，看 1s 内是否恢复数据 |
| 不用 printf 走 USB | 代码审查：USB 入口只有 `usb_link`，`printf` 只到 USART1 |
| 缓冲满丢最旧、不阻塞 | 压测：让上位机不读，看控制节拍是否还准 |

**压测方法**（很重要，评审会问）：把上位机接收线程暂停 5 秒，观察机械臂运动是否仍然
平滑 —— 因为发送走环形缓冲 + 丢最旧，主循环不会被 USB 卡住。

## 常见坑总表

| 现象 | 根因 | 解决 |
|---|---|---|
| 舵机乱抖/自己转 | 没有共地，或从板子 5V 取电 | 独立 5V 电源 + 共地 |
| 上电就烧保险/重启 | 舵机启动电流把 3.3V 拉垮 | 舵机独立电源，加 1000µF 电容 |
| USB 枚举不了 | HSE 频率填错 / PLLQ≠48MHz / PA11 复用 | 见 7.1 |
| CDC 只发一帧就停 | 忙标志竞态（已修） | 见 `bsp_usb_cdc.c` 的注释 |
| 上位机 CRC 一直错 | 字节序或 CRC 参数错 | 跑 `tools/host_test` 的示例帧对照 |
| 插补"一顿一顿" | 在中断里做 I2C/打印 | 中断只置标志，耗时活在主循环 |
| 到位差 2~3° | 软限位端点被脉宽钳位 | `servo_map_cfg_sane()` 会拒绝这种配置 |
| 录像时手抖看不清 | 没固定机械臂底座 | 底座用双面胶或夹子固定 |
