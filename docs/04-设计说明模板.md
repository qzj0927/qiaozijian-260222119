## 2 软件分层与数据流

| 层 | 文件 | 职责 |
|---|---|---|
| 行为层 | `app_main.c` `app_motion.c` `app_state.c` | 调度、插补、状态机 |
| 协议层 | `app_protocol.c` + `arm_protocol.c` | 组帧/解帧/超时/故障判定 |
| 组件层 | `motion_profile.c` `servo_map.c` `mpu6050.c` | 纯算法与传感器驱动 |
| 驱动层 | `bsp_pwm.c` `bsp_i2c.c` `bsp_usb_*.c` `bsp_time.c` | 只碰寄存器/HAL |

**优先级划分**（任务书要求说明"优先级如何划分"）：

| 优先级 | 任务 | 周期 | 执行位置 | 理由 |
|---|---|---|---|---|
| 最高 | USB 收发中断 | 事件 | 中断 | 丢包不可恢复，必须及时取走 |
| 高 | TIM6 1ms 节拍 | 1ms | 中断（只置标志） | 时基不能漂 |
| 中 | 200Hz 插补 | 5ms | 主循环 | 输出 CCR 很快，但不能被 I2C 打断 |
| 低 | I2C 采样（50Hz） | 20ms | 主循环 | 单次几十 µs~几 ms，可容忍抖动 |
| 最低 | 自检打印、状态上报 | 30Hz / 1Hz | 主循环 | 可用串口阻塞，绝不进 USB 数据路径 |

> 关键取舍：**I2C 放主循环而不是 200Hz 中断**。若放中断，一次 NAK + 超时 10ms
> 会直接吃掉两拍插补，表现为"动作中间顿一下"，T2 的"角速度无跳变"就过不了。

## 3 插补算法与参数

**归一化进度法**：不为每轴单独规划，而是规划一条 s(t) ∈ [0,1]，
各轴 `q_i(t) = q_i0 + (q_i1 − q_i0)·s(t)`。

- 天然满足"同起同停"：同一拍 s 同时到 1；
- 天然满足"增量连续"：s 是 C1 函数，相邻两拍增量 = Δq_i·Δs，无阶跃。

**梯形**（默认）：
```
s'' = ±a，中间匀速
a = 1 / (ta(T − ta))，v_peak = a·ta，ta ≤ T/2
由请求时长与限速/限加速反解 ta；请求时长过短自动延长到物理可行值
```

**S 曲线**：加速度按梯形变化（jerk 有界），取无匀速段三段式，`ta = T/2`，
此时 `a_peak = 8/T²`、`v_peak = 2/T`（归一化），起止加速度为 0。

**参数（`application/app_config.h`）**：

| 参数 | 值 | 依据 |
|---|---|---|
| 控制周期 | 5ms（200Hz） | 任务书下限 200Hz |
| 最大角速度 | 240 °/s | SG90 空载约 600°/s，带臂取 40% 稳定不丢步 |
| 最大角加速度 | 720 °/s² | 再大末端晃动明显，T2 的"平顺度"扣分 |
| 回零速度 | 90 °/s | 上电安全 |
| 状态上报 | 30Hz | 任务书 20~50Hz |
| 指令超时 | 3000ms | 任务书第 6 节 |
| I2C 故障判定 | 1000ms | 任务书 T4 |

## 4 关键取舍（答辩重点）

1. **不做笛卡尔直线插补**：考核明确不要求运动学建模，关节空间插补 + 同步已满足
   T2；代价是末端轨迹为曲线，已在演示中说明。
2. **阶跃指令强制平滑**：协议 `profile=0` 定义为阶跃，但 T2 不允许阶跃，
   固件把 0 按梯形执行（`APP_FORCE_SMOOTH_PROFILE`）。宁可慢，也不让关节"跳"。
3. **限位钳位复用 bit2**：协议没有独立限位位；急停/I2C 的 bit2 需显式复位，
   钳位的 bit2 在收到下一个合法目标时自动清除。
4. **无位置反馈**：SG90 内部闭环，指令角即实际角；堵转/撞限位会丢步，
   因此软限位比机械行程各留 5°，并在设计上避免撞限位。
5. **传输层二选一（编译期）**：CDC 与 HID 共用同一套 `usb_link` 接口，
   应用层零改动 —— 这正是任务书 4.2 想验证的"协议与传输分离"。

## 7 已知边界条件（主动说明，别等被问）

1. 无编码器，堵转/撞限位后角度模型与实际不一致，需断电重启或长按回零；
2. 负载 > 200g 时 SG90 跟随误差超 1°，T1/T3 判据会临界；
3. 电池供电时电压跌落会导致舵机抖动，建议稳压 5V；
4. I2C 线长 > 30cm 时 400kHz 可能出现 NAK，需缩短或加缓冲。
